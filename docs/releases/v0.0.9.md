# PetPlay v0.0.9

Capture helpers now build from the pinned screen-streamer submodule for each platform and are
embedded in PetPlay. Windows and Linux x64 downloads no longer carry an unrelated prebuilt
capture executable. Building from source now requires Rust and platform capture development
libraries; normal downloads do not require Rust.

- Added native Steam Frame controller bindings and a separate DroidFrame Quest engineering binding.
- Audio initialization or sound-loading failures leave the scene running silently; delayed stop
  callbacks cannot access disposed buffers.
- Added CI type-checking, unit tests, a software-OpenGL interaction smoke and platform builds.
- Included the JS interaction harness in compiled builds and corrected documentation about
  overriding live controller input.

This release publishes **Windows x64 and Linux x64** executables, checksums and third-party
notices. Linux ARM64 remains an experimental CI artifact: it includes its capture helper but
still requires ARM64 raylib. It is not attached to normal releases or advertised as a complete
Steam Frame package.

Local validation passed: type-checking with vendor filtering, 212 unit tests, software-OpenGL
smoke and keyboard playtests, Rust helper compilation, and a compiled PetPlay check that extracts
and executes the embedded helper. Platform CI is checked separately before tagging.

Quest/DroidFrame checks confirmed working trigger/grab after the engineering binding workaround.
Physical Frame controller validation remains pending. DroidFrame desktop capture still needs
session D-Bus/portal setup; lag and intermittent native shutdown faults remain under investigation.
